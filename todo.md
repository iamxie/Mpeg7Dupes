# TODO

## Inherited from upstream
- [ ] Fix broken hough transform

      Still the weakest part of the tool. The accumulator produces `score` and
      `framerateratio`, and it readily reports matches between unrelated clips
      with a `framerateratio` of 0.03 or similar, which is not a plausible
      alignment. Filtering the CSV on `framerateratio` near 1.0 and on
      `matchframes` well above `--thDi` works around it, but does not fix it.

- [ ] Verify that the signature generation code is valid

      Only matters for signatures produced by this repository. Signatures
      generated by ffmpeg's own `signature` filter do not go through this code.

- [ ] Optimize more

      Partly done: parallelising the outer loop gave more than a 10x speedup on
      12 threads. See the entry below for the next obvious win.

- [x] Fix wrong openmp usage in csv mode

      Marked done upstream in 42604d0, but the loop still carried two `ordered`
      regions per iteration, which OpenMP forbids, and in practice it still ran
      on one core. Actually fixed in 510db2e.

## This fork
- [ ] Load each signature once instead of once per comparison

      Every pair re-reads and re-parses the second signature from disk, so a
      file is parsed once for each comparison it takes part in. With 600 inputs
      that is roughly 600 parses per file. At about 1.6 MB per signature the
      whole set fits in around 1 GB of RAM, so loading everything up front and
      indexing into it should remove most of the remaining I/O and parsing cost.

- [ ] Restore grouping in `beautiful` output

      It picks its box-drawing characters from the iteration indices, assuming
      they arrive in order. They no longer do, now that the outer loop runs in
      parallel, so the tree is drawn wrong. `-f csv` is unaffected. Either
      buffer the rows and group them at the end, or drop the tree.

- [ ] Reconsider the default thresholds

      `--thDi` defaults to 300 frames of continuous match. For signatures
      sampled at 5 fps that is a full minute, so anything shorter is silently
      never reported. The right default depends on the sampling rate the
      signatures were generated at, which the tool does not know.
